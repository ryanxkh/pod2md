# REVIEW.md

## Critical Areas

- `app/api/webhooks/runpod/route.ts` — most sensitive path in the app. Multi-table DB transaction that stores transcription results. Verify transaction integrity and error handling on every change.
- `lib/db/schema.ts` — schema changes affect the entire app. Check for missing indexes, breaking column changes, and that migrations were generated (`npm run db:generate`).
- `lib/runpod/client.ts` — external API integration. Verify error handling and that request shapes match RunPod's API.
- `runpod-worker/pipeline/` — ML pipeline. Verify stage independence is maintained (each function takes input, returns output).

## Conventions

- All API routes validate input with Zod `safeParse` — flag any route accepting unvalidated `request.json()`
- Error responses use `Response.json({ error: string }, { status: N })` — flag inconsistent error shapes
- Database access uses Drizzle ORM only — flag raw SQL strings or alternative query builders
- Record IDs use nanoid via `$defaultFn` in schema — flag integer IDs, UUIDs, or manual ID generation
- Components use `"use client"` only when they need interactivity — flag unnecessary client directives (forces client-side rendering)
- Styling is Tailwind utility classes only — flag CSS modules, styled-components, or inline style objects
- Imports use the `@/*` path alias — flag relative paths that climb more than one level (`../../`)

## Ignore

- `lib/db/migrations/` — auto-generated by drizzle-kit
- `package-lock.json` — auto-generated
- `.next/` — build artifacts

## Performance

- Flag database queries inside loops (N+1 patterns)
- Flag list endpoints returning unbounded results without pagination
- Flag large objects passed from Server to Client Components (serialization cost)
